# Engineering restraint

Read the [core](core.md) and matching proposal pattern. Gather current evidence
of the problem, existing alternatives and continuing ownership cost. Inspect the
actual system or process rather than reasoning from a hypothetical feature list.

Apply the core. Resolve a Defer result's obtainable evidence before returning the
gate decision; ask only for owner judgment or unavailable access. Reconcile a
changed proposal against the protected outcome rather than silently substituting
another result. An owner-confirmed tradeoff is an input, not an invitation to
restart the same argument.

Return Reject, Defer, Reshape or Accept with reasons, smallest sufficient move,
ownership burden and reopen condition. For a disputed action, use decision-rights
to settle standing and continue within the task's authority. The assessment does
not itself implement a different design or block an owner decision by preference.
