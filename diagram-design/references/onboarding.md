# Establish a new diagram skin

Use this when the task needs an unfamiliar brand or the user asks to save a reusable skin. Establish the source, build a usable treatment, and verify it in the requested artifact. Ordinary onboarding does not rewrite the shared installed guide.

## Resolve source and scope

Prefer supplied or authoritative brand tokens and assets. Read the active skill catalog or explicit path for an existing brand guide before searching unrelated agent directories. If the source is a website, inspect the real rendered surface and its styles; if it is a project, inspect the relevant token definitions and the components that consume them. Use a bounded search to identify the actual authority rather than reading every file matching color or font.

Distinguish official identity rules, observed product styling, and a proposed diagram adaptation. A website's incidental button color is not automatically the brand accent. A dark theme is not necessarily an inversion of the light theme. Record what is sourced and what is a reversible design choice.

Determine whether the request is task-local, project-persistent, or an explicit update to a named shared profile. Existing authorization can settle this. If persistence is unspecified, produce the task-local artifact first; do not change defaults for future work.

## Build the smallest complete skin

Map source values to semantic roles: paper, secondary surface, ink, muted text, rules, emphasis, links, status, and any chart series. Preserve meaning when translating source roles. A failure color must not become a generic optional-edge color. Use enough distinguishable series colors for the actual data, with labels or redundant marks.

Identify the intended text family and weights. CSS computed font-family shows the declared stack, not proof that the desired font loaded. Check font availability and loading, then inspect the rendered text and fallback state. Use supplied or authorized local assets for standalone exports. If the actual brand font is unavailable, make the substitution explicit rather than calling the result exact brand fidelity.

Apply shape and spacing conventions only where useful. Diagrams may need smaller technical labels than a marketing page, but material adaptations should remain clear. Keep diagrams readable and honor source-sensitive notation even when the brand prefers a different decorative treatment.

## Verify and persist within scope

Render a representative part of the actual requested diagram with long labels, secondary text, an edge, a status distinction, and the chosen theme. Inspect the real destination or export. Check contrast, font substitution, line visibility, and label collisions. Repair the skin before applying it to all figures.

If persistence is authorized, save a project-local guide or a named external profile using [profiles](profiles.md), recording sources, role mappings, theme limits, and adaptations. Show the meaningful changes, including typography rather than only color. Shared installed guides are changed only when the user explicitly asks to maintain those guides. Do not add routine confirmation when the requested scope is already authorized.
