# Creative ideation

Read the [core](core.md), then the route and method it selects. Acquire the actual
brief, existing material, constraints, previous attempts and user choices. This
one entry serves both blank-page generation and shaping existing work.

Resolve the core's evidence needs from available sources; ask only for genuinely
missing owner input. For method recommendations, present its 2–3 candidates and
let the user choose. Do not silently apply one. For ambiguity, ask its single
question and feed the answer back.

Method recipes include research, interviews, group work, physical exercises,
random draws and prototypes. The shell owns those operations within task
authority. A core can propose them; only actual observations establish their
results. Do not invent customer interviews, drift notes, independent participants,
random draws or elapsed practice. For a timed exercise, guide the selected
activity and assess what the user actually returns; do not promise an idea on a
schedule or start recurring work without a request.

Deliver the method-specific result with attribution and the core's quality floor.
When the user chooses a direction, stop generating alternatives and move into the
requested making work; preserve scope and existing authority. A request for ideas
alone does not authorize publishing or external actions.
